Low Power Assistant (LPA) middleware library - Wi-Fi, Bluetooth®, and MCU low-power configuration for Infineon devices

Overview

The Low Power Assistant (LPA) middleware provides an easy, portable configuration layer that makes the low-power features of Infineon MCUs, Wi-Fi, and Bluetooth® radios available to developers. It lets you configure MCU sleep and System Deep Sleep, Wi-Fi WLAN firmware offloads (ARP, packet filters, TCP keepalive, and more), and Bluetooth® low-power wake signaling — reducing host power consumption by keeping the host MCU asleep while the WLAN device handles routine network traffic on its behalf.

LPA is essentially a Wi-Fi offload manager (OLM) that is instantiated when the Wi-Fi Connection Manager (WCM) is initialized. The offload manager applies the offload configurations that you create with the ModusToolbox™ Device Configurator. The LPA library only needs to be included in applications that use low-power Wi-Fi operation.

The LPA middleware consists of the following components:

  • A Configurator personality that makes the system's low-power features easy to use. This personality writes the data structures; after the configuration is saved, it generates cycfg_connectivity_wifi.h / cycfg_connectivity_wifi.c for PSOC™ 6, and cycfg_peripherals.h / cycfg_peripherals.c for CYW955913EVK-01, based on the settings made in the Device Configurator.
  • The generated source files, which are compiled and linked into the executable and invoked at system initialization.

The Device Configurator manages the pin configurations for CYBSP_WIFI_HOST_WAKE, CYBSP_WIFI_DEVICE_WAKE, CYBSP_BT_HOST_WAKE, and CYBSP_BT_DEVICE_WAKE, together with the offload configurations.

Note: Pin configurations are not applicable for CYW955913EVK-01.

For complete configuration details, per-offload quick start guides, and power-measurement instructions, see the Low Power Assistant (LPA) Datasheet.

Features

  • MCU low power (CPU Sleep and System Deep Sleep)
  • Wi-Fi and Bluetooth® low power
  • Wi-Fi host-wake signal (out-of-band host wake)
  • Wi-Fi Address Resolution Protocol (ARP) offload
  • Wi-Fi packet filter offload
  • Wi-Fi TCP keepalive offload
  • DHCP Lease Time Renew offload (DLTRO)
  • ICMP offload
  • Neighbor Discovery offload (NDOE)
  • NULL keepalive offload
  • NAT keepalive offload
  • Wake on Wireless LAN (WOWLPF)
  • MQTT keepalive offload
  • Bluetooth® low power

When to Use

Use the LPA middleware when you are building an RTOS-based (FreeRTOS or ThreadX) connected application on a supported Infineon device and need to minimize host power consumption. Typical scenarios include:

  • Battery-powered or energy-harvesting IoT end nodes that must stay associated with a Wi-Fi network while the host MCU spends most of its time in System Deep Sleep.
  • Applications that must remain reachable (ARP, ping/ICMP, neighbor discovery) or keep TCP/MQTT/NAT sessions alive without waking the host for every packet.
  • Designs that want the WLAN firmware to filter unwanted broadcast/multicast traffic so the host is woken only for relevant packets.
  • Designs that need the WLAN device or Bluetooth® controller to wake the host from low power through a dedicated host-wake pin.

The LPA provides features for MCU, Wi-Fi, and Bluetooth® low power; however, the library only needs to be included in applications that use Wi-Fi low power.

Prerequisites

Hardware Requirements

  • One of the supported Infineon kits (see Supported platforms).

  • For host-wake / device-wake functionality, the board must route the WLAN and Bluetooth® wake signals to the host through CYBSP_WIFI_HOST_WAKE, CYBSP_WIFI_DEVICE_WAKE, CYBSP_BT_HOST_WAKE, and CYBSP_BT_DEVICE_WAKE. These pins are configured in the Device Configurator.

    Note: Pin configurations are not applicable for CYW955913EVK-01.

  • The CY8CKIT-062S2-43012 kit is recommended when following the power-measurement instructions in the Reference Manual, because those instructions are documented for that kit.

Add Required Libraries

Add the required middleware using the ModusToolbox™ Library Manager (available in the ModusToolbox™ for VS Code extension and the Eclipse IDE) or by creating the corresponding .mtb files in the application's deps folder and running make getlibs.

  • For FreeRTOS-based applications, add wifi-core-freertos-lwip-mbedtls. This internally pulls in wifi-connection-manager, FreeRTOS, lwIP, mbed TLS, and the other dependent modules.

    Note: LPA currently supports wifi-core-freertos-lwip-mbedtls latest-v1.X only.

  • For ThreadX-based applications (currently supported only on CYW955913EVK-01), add wifi-core-threadx-cat5. This internally pulls in wifi-connection-manager and the other dependent modules.

The LPA library itself is pulled in as a dependency of these Wi-Fi core libraries; the ModusToolbox™ Wi-Fi low-power code examples download it automatically.

Configure Makefile (if applicable)

MCU Deep Sleep functionality is enabled by default. For FreeRTOS on PSOC™ 6, confirm tickless idle is enabled in FreeRTOSConfig.h:

#include <cycfg_system.h>
#if (CY_CFG_PWR_SYS_IDLE_MODE == CY_CFG_PWR_MODE_SLEEP) || (CY_CFG_PWR_SYS_IDLE_MODE == CY_CFG_PWR_MODE_DEEPSLEEP)
extern void vApplicationSleep( uint32_t xExpectedIdleTime );
#define portSUPPRESS_TICKS_AND_SLEEP( xIdleTime ) vApplicationSleep( xIdleTime )
#define configUSE_TICKLESS_IDLE 2
#endif
/* Deep Sleep Latency Configuration */
#if CY_CFG_PWR_DEEPSLEEP_LATENCY > 0
#define configEXPECTED_IDLE_TIME_BEFORE_SLEEP CY_CFG_PWR_DEEPSLEEP_LATENCY
#endif

On CYW955913EVK-01, MCU Deep Sleep is enabled by default and no FreeRTOSConfig.h change is required.

Configure in the Tool (if applicable)

Configure LPA using the ModusToolbox™ MCU/Power, Wi-Fi, and Bluetooth® personalities in the Device Configurator. Open it with make device-configurator (or from the IDE), enable the required personality, set the offload and wake-pin parameters, and save to generate the initialization code. For the complete per-offload parameter reference, see the Configuration Reference, the Low Power Assistant (LPA) Datasheet, and the ModusToolbox™ Device Configurator tool guide.

Add Headers

LPA is configured primarily through the Device Configurator-generated sources, which the BSP includes automatically; the offload APIs are pulled in through the Wi-Fi core libraries, so no additional header is required for basic use. To control LPA log verbosity from application code, include the offload debug header:

#include "cy_lpa_wifi_ol_debug.h"

Quick Start

This quick start demonstrates the most common use case: enabling MCU and Wi-Fi low power so the host enters System Deep Sleep while connected to a Wi-Fi network and wakes on relevant traffic through the WLAN host-wake signal. Follow these steps to get from an Empty template to a working example:

Step 1: Create an Empty application for your kit (for example, mtb-example-psoc6-empty-app for CY8CKIT-062S2-43012), or start from the WLAN low-power code example.

Step 2: Add the Wi-Fi core library for your RTOS (see Add Required Libraries) using the Library Manager or by adding the .mtb files and running make getlibs.

Step 3: In the Device Configurator, enable the Power personality, set System Idle Power Mode to System Deep Sleep, and enable the Wi-Fi host-wake configuration (set the host device interrupt pin to CYBSP_WIFI_HOST_WAKE). Save to generate the initialization code.

Step 4: Copy the latest FreeRTOSConfig.h into the application root and confirm tickless idle is enabled (see Configure Makefile).

Step 5: Add the following code to your main.c (see Sample Code for the complete example), then build and program.

Expected Outcome: The host connects to the configured Wi-Fi AP and enters System Deep Sleep during idle. Incoming traffic (for example, a ping) asserts the WLAN host-wake line and wakes the host; the offloads keep the connection alive while the host sleeps. Full details in Expected Outcome.

Sample Code

FreeRTOS Example (main.c)

This example demonstrates MCU low power in a FreeRTOS application. The system enters System Deep Sleep while idle; the user LED indicates the Active (LED on) versus Idle (LED off) states for power measurement.

#include "cy_pdl.h"
#include "cyhal.h"
#include "cybsp.h"
#include "FreeRTOS.h"
#include "task.h"
#define BLINKING_RATE_MS 5000
static void blinky(void *args)
{
TickType_t ticks = pdMS_TO_TICKS(BLINKING_RATE_MS);
/* Initialize the User LED */
cyhal_gpio_init((cyhal_gpio_t)CYBSP_USER_LED, CYHAL_GPIO_DIR_OUTPUT, CYHAL_GPIO_DRIVE_STRONG, CYBSP_LED_STATE_OFF);
while (true)
{
/* Turn ON LED (Active state) */
cyhal_gpio_write((cyhal_gpio_t)CYBSP_USER_LED, false);
/* Delay so the MCU stays active and does not enter Deep Sleep */
cyhal_system_delay_ms(BLINKING_RATE_MS);
/* Turn OFF LED (Idle state) */
cyhal_gpio_write((cyhal_gpio_t)CYBSP_USER_LED, true);
vTaskDelay(ticks);
}
}
int main(void)
{
cy_rslt_t result;
/* Initialize the device and board peripherals */
result = cybsp_init();
if (result != CY_RSLT_SUCCESS)
{
CY_ASSERT(0);
}
__enable_irq();
xTaskCreate(blinky, "Blinky Task", 1024 * 10, 0, 1, 0);
/* Start the FreeRTOS scheduler */
vTaskStartScheduler();
}

For the complete Wi-Fi host-wake and per-offload examples (ARP, packet filter, TCP keepalive, and others), see the per-offload quick start guides in the Low Power Assistant (LPA) Datasheet and the Related Code Examples.

On CYW955913EVK-01, MCU low power is enabled by default. Start from mtb-example-threadx-cyw5591x-low-power, then build and program:

make getlibs

Expected Outcome

When you successfully run the Quick Start example, you should observe:

Visual/Hardware Behavior:

  • The host MCU connects to the configured Wi-Fi AP, then enters System Deep Sleep during idle. On PSOC™ 6 kits, the user LED shows the Active (on) versus Idle (off) states.
  • Sending traffic (for example, a ping) to the board asserts the WLAN host-wake (out-of-band) line and wakes the host to service the packet, after which it returns to System Deep Sleep.

Terminal Output:

Network Stack Suspended, MCU can enter DeepSleep power mode
Resuming Network Stack, Network stack was suspended for 15253ms
...
oob_intrs:72, sdio_intrs:147, error_intrs:0, read_aborts:0
Network Stack Suspended, MCU can enter DeepSleep power mode

The oob_intrs counter reflects the number of WLAN out-of-band interrupts (host wakes) received.

Note: On CY8CEVAL-062S2-CYW43022CUB, ICMP ping is offloaded to the WLAN firmware, so ping traffic does not wake the host. Send TCP/UDP packets to verify host wake.

Performance Metrics:

  • With MCU and Wi-Fi low power enabled, the host remains in System Deep Sleep between offloaded events. Refer to the power-measurement instructions in the Reference Manual (documented for CY8CKIT-062S2-43012) to quantify current consumption in the Active versus Deep Sleep states.

Troubleshooting

  • Host never enters Deep Sleep: Ensure the System Idle Power Mode is set to System Deep Sleep in the Device Configurator Power personality, and that tickless idle is enabled in FreeRTOSConfig.h (PSOC™ 6). A task that never blocks (for example, a busy delay) keeps the MCU active by design.
  • Host does not wake on incoming traffic: Verify the Wi-Fi host-wake configuration and that the host device interrupt pin is set to CYBSP_WIFI_HOST_WAKE. Host-wake is required for the WLAN offloads to wake the host.
  • Ping does not wake the host on CY8CEVAL-062S2-CYW43022CUB: ICMP is offloaded to the WLAN firmware; use TCP/UDP traffic to observe host wake.
  • Wrong Wi-Fi core version: LPA currently supports wifi-core-freertos-lwip-mbedtls latest-v1.X only.
  • Enable debug logging: To print offload debug, log, and error messages, set the relevant ol_log_level[] entries to LOG_OLA_LVL_DEBUG:
    ol_log_level[LOG_OLA_OLM] = LOG_OLA_LVL_DEBUG;

    ol_log_level[LOG_OLA_PF] = LOG_OLA_LVL_DEBUG;

Configuration Reference

LPA is configured through the ModusToolbox™ Device Configurator personalities (MCU/Power, Wi-Fi, and Bluetooth®), which generate the initialization sources that LPA consumes at startup. The complete set of configuration parameters — MCU System Idle Power Mode and Deep Sleep Latency, host-wake pins, and the per-offload parameters for ARP, packet filter, TCP keepalive, DLTRO, ICMP, NDOE, NULL keepalive, NAT keepalive, WOWLPF, and MQTT keepalive — is documented in the Low Power Assistant (LPA) Datasheet.

Key generated sources:

  • PSOC™ 6: cycfg_connectivity_wifi.c / cycfg_connectivity_wifi.h
  • CYW955913EVK-01: cycfg_peripherals.c / cycfg_peripherals.h

Debug logging is controlled at runtime through the ol_log_level[] array (see Troubleshooting).

For library limitations, see the Low Power Assistant (LPA) Datasheet. For tool usage, see the ModusToolbox™ Device Configurator tool guide.
